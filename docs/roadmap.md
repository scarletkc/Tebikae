# 后续扩展

第一版实现范围是架构文档的 F01–F18。下列项目保持为后续工作，不是当前运行依赖。

## P1

- 在已实现的浏览器自动恢复之外，增加可选的本地口令保护；独立设计密钥派生、忘记口令与明文缓存的说明。
- 多仓库、多账号切换；复用现有稳定 scope 隔离。
- 评论、标签重命名／删除、图片与附件。

JSON 备份导入和批量 Markdown ZIP 导出已在设置页提供。导入支持逐项校验、预览与选择、重复检测，以及目标仓库的同名标签匹配；恢复为独立副本，不覆盖原笔记。

## P2：MCP 与 Skill

先提供独立本地 stdio MCP 服务，通过单独配置的凭证读写相同笔记协议。服务不读取网页 Token，不要求网页保持打开，也不将 AI SDK 放进静态网页。

复用 Domain、字段验证、合并与 GitHub Adapter。工具分别提供查询、创建、编辑、归档、回收站和标签操作；使用稳定仓库／Issue 身份、修订摘要与 request ID 核对冲突和未知结果。

Skill 负责说明何时调用工具、如何查找后编辑、保留未知元数据、处理冲突，以及把笔记正文视作资料而非工具指令。完整设计见[架构文档第 15 节](github-issues-notes-product-architecture.md#15-后续事项ai-插件集成mcpskill)。

OAuth / GitHub App、远程 MCP、组织协作与公开笔记需要各自授权和部署设计，不预先改变当前私人仓库直连架构。

## P3：桌面与移动 App

- 推出桌面 App，覆盖 Windows、macOS 和 Linux。
- 推出 iOS 与 Android App。
- 沿用 GitHub Issues 笔记协议，支持网页、桌面与移动端之间的笔记同步。

各平台的发布、签名、更新机制与凭证本地安全存储另行设计。此阶段属于未来规划，技术选型与发布时间待定。
