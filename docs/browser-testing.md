# 浏览器测试分层

本文说明 CI 如何选择浏览器用例，以及如何在本地复现。贡献者提交前的验证要求见[贡献指南](../CONTRIBUTING.md#validation)。

## 运行时机

| 触发方式                                                    | 浏览器覆盖                                                                |
| ----------------------------------------------------------- | ------------------------------------------------------------------------- |
| 含代码改动的 PR                                             | Chromium 核心流程、相关 E2E 和完整 PWA；关键路径增加相关跨浏览器测试      |
| main 代码推送                                               | 静态检查、全量单测和根路径构建，不运行浏览器测试                          |
| 仅根目录 Markdown、`docs/` 内 Markdown 或 LICENSE 改动的 PR | `plan` 明确识别后，汇总 `check` 通过，不运行代码检查                      |
| 仅上述文档改动的 main 推送                                  | 不触发 `Check`                                                            |
| 手动运行 `Check`                                            | 三浏览器全量 E2E／PWA                                                     |
| 运行 `Deploy Pages`                                         | 要求目标提交已通过三浏览器全量 E2E／PWA；没有可复用的已验证产物时重新验证 |

`@smoke` 核心流程复用现有用例，覆盖连接与只读打开、可视化编辑后的本地保存和同步、刷新自动重连，以及离线编辑后的重开。E2E 验证开发服务器中的界面交互；PWA 用例验证生产构建的离线恢复、更新和部署路径。

## 根据改动增加覆盖

[选择脚本](../scripts/ci-browser-plan.mjs) 的 `browserPlan()` 定义路径与测试的映射。PR 使用共同祖先到 head 的差异；删除和重命名前后的路径都参与选择，多种改动取并集。`plan` 的摘要给出本次实际选择的浏览器、`grep` 和 PWA 开关，以及全量兜底的原因。

| 改动                                                         | PR 覆盖                                                       |
| ------------------------------------------------------------ | ------------------------------------------------------------- |
| 编辑器、Markdown、笔记编辑对话框和编辑快捷键                 | 三浏览器的编辑、保存竞态和可靠性用例，以及完整 PWA            |
| 存储、同步、GitHub adapter、凭证、连接、写入命令和持久化协议 | 三浏览器的会话、同步重试、备份导入和可靠性用例，以及完整 PWA  |
| 共享界面组件、样式和翻译                                     | Chromium 中覆盖布局、编辑器控件、菜单和导入导出对话框的用例   |
| 标签、筛选、工作区、笔记卡片和设置等功能                     | Chromium 中与该功能相关的用例                                 |
| 单个 E2E 测试文件                                            | Chromium 中该文件的全部用例，保留核心流程以覆盖删除用例的情况 |
| PWA 测试或配置                                               | 三浏览器的持久化相关 E2E 和完整 PWA                           |
| 浏览器共享 fixture、E2E 配置、入口、静态资源和构建依赖       | Chromium 全量 E2E 和 PWA                                      |
| CI、静态检查工具和顶层单测                                   | 静态检查、单测，外加 Chromium 核心流程和 PWA                  |
| 未分类路径或无法读取 PR 比较信息                             | Chromium 全量 E2E 和 PWA，摘要显示兜底原因                    |

每个被选中的浏览器都保留 `@smoke` 核心流程。关键路径增加的跨浏览器用例独立取并集，普通界面改动不会把其他浏览器一并扩成全量。应用单测始终完整运行。涉及广泛兼容性变化时，可以手动运行 `Check` 做三浏览器全量验证。

文档与代码混合变更正常验证，`docs/` 下的脚本或资源也参与选择。新增用例或模块时，应检查选择脚本是否覆盖它；规则的回归测试位于 [tests/ci/browser-plan.test.mjs](../tests/ci/browser-plan.test.mjs)。

## 重复提交与缓存

同一 PR 的新提交取消正在运行的旧检查，最新提交重新执行所选检查。普通 PR 不使用通过结果缓存。文档-only 按整个 PR 的差异判断，因此代码 PR 后续追加文档仍需执行该 PR 的检查。发布保持串行，不取消进行中的部署。

pnpm 缓存保存下载的包；新 runner 仍执行锁文件安装来恢复依赖结构。Playwright 浏览器文件按系统、架构、系统镜像系列、引擎和准确版本单独缓存，命中时不重新下载；系统依赖仍在当前 runner 安装。发布产物的验证与复用规则见[部署说明](development.md#github-pages)。

## 查看结果

浏览器任务分别安装所需引擎并行运行，复用同一次生产构建。失败截图、trace 和 HTML 报告按浏览器保存为 `browser-test-results-<browser>` artifact。诊断失败时，先查看对应浏览器任务的日志和报告。

汇总 `check` 通过 [checksPassed()](../scripts/ci-check-result.mjs) 校验结果：文档-only PR 的代码和浏览器任务必须按计划跳过；main 的代码检查必须成功、浏览器任务必须跳过；选择了浏览器测试的运行必须全部成功。失败、取消、缺失输出或意外跳过都会导致汇总失败。[Check 工作流](../.github/workflows/check.yml)定义任务依赖。

## 本地复现

运行日常 PR 的 Chromium 核心流程：

```sh
pnpm exec playwright install chromium
pnpm test:e2e --project=chromium --grep '@smoke'
```

精确复现一个 PR 时，使用 `plan` 摘要中该浏览器对应的 `grep`，并按 PWA 开关运行生产测试。需要完整跨浏览器 E2E 时，安装全部引擎并运行默认命令：

```sh
pnpm exec playwright install
pnpm test:e2e
```

`pnpm test:e2e` 和 `pnpm test:pwa` 默认选择全部引擎。生产构建和 PWA 的运行方法见 [PWA 验收说明](testing-pwa.md)，定向测试与静态检查命令见[开发指南](development.md#检查)。

E2E 的默认并发数和重试策略由 [playwright.config.ts](../playwright.config.ts) 中的 `workers` 和 `retries` 控制，本地并发数不随 CPU 核心数增长。需要调整并发或重复排查偶发失败时，可以覆盖运行参数：

```sh
pnpm test:e2e --project=chromium --workers=4 --repeat-each=3 --retries=0
```

浏览器自动化不能替代真机软键盘、中文输入法、iOS 独立 PWA 和系统存储回收验证。PWA 验收记录中的结果对应其注明的日期，不代表当前分支已通过检查。
